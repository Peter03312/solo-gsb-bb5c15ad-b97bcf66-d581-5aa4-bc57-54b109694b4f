# 排练字幕修订 Web 应用

本地运行的排练字幕（SRT）修订工具。导入 SRT 原稿后，可在**两条独立的修订分支**上修正文案与起止时间、拆分/合并片段；合并时按**来源片段**做三方比对，双方同时改动的片段会并列展示并由人工选择，未冲突改动自动保留。导出前强制时间线校验，并可随时查看/恢复原稿。

在修订分支或合并分支上还可执行**可复核的放映质检（QC）**：为每份稿件配置质检规则（单条显示时长上下限、每秒可见字符数上限、相邻片段最小间隔、禁用词），按当前文字与时码生成报告、逐条列出命中与原稿来源；可对具体命中填写**有严格时效的豁免**，全部命中处理完且时间线无误后才能通过质检专用下载导出 SRT。

视频重剪后，可在任一修订分支或合并分支上对一段**连续的原稿来源序号区间**做**可预览的时码重排**：区间内片段保持相对位置等比重排，区间之后整体平移，区间之前不动；先预览每条受影响片段的新旧时码与时间线问题，确认后才整体提交。

## 功能

- **导入 SRT**：严格校验序号连续、时间码格式、起点早于终点、片段不重叠；发现错误时列出具体行号与原因并**拒绝整份稿件**（不写入任何数据）。
- **双修订分支**：每份原稿导入时自动建立「修订分支 A / B」，各自独立编辑，互不影响。
- **片段编辑**：修改文案、起止时间；按时间码拆分片段；与下一片段合并；单片段恢复原稿；整条分支重置。
- **三方合并**：
  - 只被一方改动的来源区间 → 自动保留该方改动；
  - 双方都触及同一来源区间（含拆分/合并边界不同）→ 标记为冲突，并列展示 A/B 各自完整内容，必须逐处选择采用哪一方，**不以保存先后覆盖**；
  - 双方都未动 → 保留原稿；
  - 合并结果保存为新分支（含来源关联，可再次合并/导出/质检）。
- **放映质检（QC）**：
  - **规则配置（按稿件）**：单条显示时长下限/上限（秒）、每秒可见字符数上限（字符/秒）、相邻片段最小间隔（秒）、禁用词；空白不计字符，中文字符与标点各算一字；阈值留空表示该项不启用。无效阈值（≤0、非数字、下限大于上限）、空词、重复词一律**拒绝保存**。
  - **规则版本化**：规则内容实质变化时归档为新版本；豁免只对创建时的规则版本有效，规则变化后须用新版本重新生成报告。
  - **质检报告**：在修订分支或合并分支上按当前文字与时码生成，逐条列出命中规则、片段序号、原稿来源序号、时间码与具体原因，同时列出时间线问题；报告是生成时刻的快照，**编辑、拆分或合并后旧报告立即标记失效，不得沿用旧结果**，须重新生成。
  - **逐条豁免**：可对某条命中填写豁免理由；豁免仅对该分支当时的片段内容、时码与规则版本有效——片段文案/时码再变（含拆分、合并、恢复原稿）、片段消失或规则版本变化，豁免自动失效并在新报告中列明失效原因；也可手动撤销豁免。
  - **质检专用下载**：导出时**重新实时核验**当前分支片段、当前规则、当前豁免与时间线；仍有未豁免命中、时间线错误或报告已失效时**不生成 SRT** 并返回具体问题清单；全部通过后导出序号从 1 连续编号的 SRT。
- **导出校验（原有）**：检查时间非负、起点早于终点、片段不重叠；失败时列出问题片段序号与原因，**不生成文件**；通过后导出序号从 1 连续编号的 SRT。
- **重剪重排（本轮新增）**：在任一修订/合并分支上选择连续原稿来源序号区间 `[lo, hi]` 并填写该区间在新版视频中的起止时码：
  - **区间之前**的片段时码完全不动；
  - **区间内完整片段**按原有相对位置等比重排（线性映射 `新位置 = 新起点 + (原位置 − 原起点) × (新区间时长 ÷ 原区间时长)`，同一拆分切点只舍入一次，不会错开）；
  - **区间之后**的片段按「新区间终点 − 原区间终点」整体平移；
  - **结构约束**：同一来源拆出的片段必须一起处理（同在内或同在外）；跨越选择边界的合并片段（来源集合横跨 `lo`/`hi`）一律拒绝；区间内每个来源序号都必须能在分支上找到对应片段；
  - **两段式确认**：先调用预览接口/点「生成预览」，逐条展示受影响片段的新旧时码、角色（区间内/区间后）、是否实际变化，以及换算问题（负时码、等比重算后零时长）与时间线问题；预览返回一次性令牌。预览后分支被编辑、拆分、合并或重置，提交返回 409 并要求重新预览；
  - **原子提交**：确认在单事务内完成，整体成功或不改动；无效区间、新区间非正时长、负时码、片段重叠、换算后片段时长为零均给出原因并拒绝；
  - 只有**换算后时码确实变化**的片段才推进修订计数，使对应旧质检豁免/旧报告失效；时码未变的片段不会被误判为改动，既有豁免继续有效；质检导出仍按当前状态实时核验。
- **原稿管理**：在线查看原始 SRT、一键下载原稿、删除稿件。

## 技术栈

- 后端：Node.js 20 + Express
- 数据库：SQLite（better-sqlite3，同步事务，WAL 模式，外键级联）
- 前端：原生 HTML/CSS/JavaScript（无需构建）
- 部署：Docker / Docker Compose（多阶段镜像内含依赖安装与数据库自动初始化）

## 快速开始（Docker Compose，推荐）

需要 Docker 20.10+ 与 Docker Compose v2。

```bash
docker compose up -d --build
```

启动后访问：

- **http://localhost:3000**

停止：

```bash
docker compose down          # 保留数据
docker compose down -v       # 同时删除数据库卷
```

### 配置

通过环境变量配置（可写入项目根目录的 `.env` 文件）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | 宿主机映射端口（容器内固定监听 3000） |
| `PORT` | `3000` | 容器/进程监听端口（直接用 Node 运行时生效） |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | SQLite 数据库目录（Compose 中为命名卷 `/app/data`） |
| `DB_PATH` | `$DATA_DIR/app.db` | 数据库文件完整路径 |

例如改用 8080 端口：

```bash
APP_PORT=8080 docker compose up -d --build
# 访问 http://localhost:8080
```

数据保存在 Docker 命名卷 `srt-data` 中，重建容器不会丢失。

## 直接用 Node.js 运行（不使用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

数据库文件在首次启动时自动创建于 `./data/app.db` 并完成全部建表初始化，无需手动导入 SQL。

## 使用说明

1. 点击右上角 **导入 SRT**，选择本地 `.srt` 文件；若格式有误，弹窗会逐条列出「第 N 行」的错误，修正后重新导入即可。
2. 在顶部标签切换 **修订分支 A / B**，直接在表格中编辑文案与时间码，逐行点 **保存**；
   - **拆分**：输入切点时间码，把一条切成两条，两条均继承原来源；
   - **与下条合并**：合并相邻两条，来源取并集，时间取外边界，之后可再调整文案；
   - **恢复原稿**：把单条还原为原稿内容；**整条重置为原稿** 会丢弃该分支全部修改。
3. 两条分支修订完成后，点击 **合并两条分支**：
   - 预览每组来源区间的处理方式（未改动 / 仅 A 改 / 仅 B 改 / 冲突）；
   - 冲突处点击左侧或右侧卡片选择采用 A 还是 B，全部选择后生成合并分支。
4. 在合并分支（或任意分支）上点 **导出前检查**；通过后点 **导出 SRT** 下载序号连续的文件；检查不通过时按提示修复，服务器同样会拒绝生成文件。
5. **放映质检（本轮新增）**：
   1. 点右上角 **质检规则**，按需填写单条显示时长上下限（秒）、每秒可见字符数上限、相邻片段最小间隔（秒）与禁用词（每行一个）；无效阈值、空词或重复词会被拒绝保存。规则实质修改会产生新版本。
   2. 切换到任意修订分支或合并分支，在页面底部 **放映质检** 面板点 **生成质检报告**：报告会按当前文字与时码列出每条命中的规则、片段序号、原稿来源、时间码与原因，以及时间线问题。
   3. 对可接受的命中点 **填写豁免理由**。豁免只对此分支当前片段内容、时码与规则版本有效；之后改文案、改时间、拆分、合并、恢复原稿或修改规则，豁免立即失效（新报告会列出失效原因），需要重新评估；也可随时 **撤销豁免**。
   4. 编辑/拆分/合并后旧报告会在面板顶部红色提示「不得沿用」，此时请 **重新生成质检报告** 再处理。
   5. 点 **质检专用下载**：服务器重新核验当前片段、规则、豁免与时间线；存在未豁免命中、时间线错误或报告失效时不生成 SRT，并逐条返回具体问题；全部通过后才下载连续编号的 SRT。
6. **重剪重排（本轮新增）**：切换到任意修订分支或合并分支，点工具栏 **重剪重排**：
   1. 填写连续的**来源起始/结束序号**与该区间在新版视频中的**新起点/新终点时码**（`HH:MM:SS,mmm`），点 **生成预览**；
   2. 预览中显示原区间→新区间、等比系数、区间后平移量，以及每条受影响片段（区间内等比、区间后平移）的新旧时码；区间前片段不在列表中（不动）；
   3. 若存在换算问题（换算后负时码、等比重算后零时长）或时间线问题（起点不早于终点、片段重叠等），问题逐条列出且 **确认提交** 禁用；跨界合并片段、无效区间会直接拒绝并给出原因；
   4. 核对无误后点 **确认提交**：服务器校验预览令牌——预览后该分支若被编辑、拆分、合并或重置，会返回「预览已过期」，请重新生成预览；提交整体成功或不改动。提交后时码实际变化的片段旧质检豁免/旧报告自动失效，未变化片段不受影响（请按第 5 步重新生成质检报告）。
7. 顶部 **查看原稿 / 下载原稿** 可随时对照与恢复原始稿件。

## SRT 格式要求

```
1
00:00:01,000 --> 00:00:04,000
第一句台词

2
00:00:04,500 --> 00:00:07,200
第二句台词（可多行）
```

- 序号必须从 1 开始且连续；
- 时间码格式 `HH:MM:SS,mmm --> HH:MM:SS,mmm`；
- 每条至少一行非空正文；
- 起点严格早于终点，相邻片段时间不重叠。

## 数据模型（简述）

- `scripts`：稿件与原始 SRT 全文；
- `source_segments`：解析后的原稿片段（合并识别的基准）；
- `branches`：修订分支与合并结果分支；
- `branch_segments`：分支上的当前片段（`rev` 为片段修订计数，文案/时码任一变化即 +1，驱动豁免失效）；
- `segment_sources`：分支片段 ↔ 来源片段多对多关联（拆分=一对多，合并=多对一）；
- `qc_rules` / `qc_rule_versions`：每稿件当前质检规则指针 + 历史版本归档；
- `qc_reports` / `qc_hits`：质检报告快照与其命中（规则、片段序号、原稿来源、原因），附生成时的分支状态指纹与时间线问题；
- `qc_exemptions`：逐条命中豁免，绑定分支、规则版本、片段 id 与 `rev`、命中指纹，片段或规则任一变化即失效。

合并算法以来源序号为轴遍历，依据双方在同一区间的区块（普通/拆分/合并）决定自动保留或提请冲突选择。

重剪重排不新增数据表：预览令牌是「分支片段状态指纹（身份/顺序/时码/文案/来源/rev）+ 重排参数」的哈希（无状态）；提交在单事务内批量更新时码，仅换算后时码实际变化的片段 `rev = rev + 1`，因此旧豁免/旧报告只对真正变动的片段失效，未变化片段不被误判。

质检判定以当前片段实时计算为准：报告用于可复核留档与豁免操作，质检导出闸门不依赖旧报告，而是重新核验分支、规则、豁免与时间线。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/scripts` | 上传 SRT（multipart 字段 `file`，可选 `name`） |
| `GET` | `/api/scripts` | 稿件列表 |
| `GET` | `/api/scripts/:id` | 稿件详情（来源片段 + 分支） |
| `DELETE` | `/api/scripts/:id` | 删除稿件 |
| `GET` | `/api/scripts/:id/original[.srt]` | 查看/下载原稿 |
| `GET` | `/api/branches/:id` | 分支及片段 |
| `PATCH` | `/api/branches/:id` | 重命名分支 |
| `PATCH` | `/api/branches/:id/segments/:sid` | 改文案/起止时间 |
| `POST` | `/api/branches/:id/segments/:sid/split` | 拆分（`cut_ms`） |
| `POST` | `/api/branches/:id/segments/:sid/merge-with-next` | 与下条合并 |
| `POST` | `/api/branches/:id/segments/:sid/reset` | 单条恢复原稿 |
| `POST` | `/api/branches/:id/reset-all` | 整条重置 |
| `POST` | `/api/branches/:id/recut/preview` | 重剪重排预览（返回受影响片段新旧时码、问题清单与一次性令牌 `token`） |
| `POST` | `/api/branches/:id/recut/apply` | 凭令牌确认重排（整体成功或不改动；令牌过期 409，校验问题 400） |
| `POST` | `/api/merge/preview` | 合并预览（冲突清单） |
| `POST` | `/api/merge/apply` | 提交冲突选择并生成合并分支 |
| `GET` | `/api/branches/:id/validate` | 导出前时间线检查 |
| `GET` | `/api/branches/:id/export` | 导出连续编号 SRT（原有，时间线校验） |
| `GET` | `/api/scripts/:id/qc-rules` | 读取当前质检规则（未配置返回 `configured:false`） |
| `PUT` | `/api/scripts/:id/qc-rules` | 保存质检规则（400 拒绝无效阈值/空词/重复词；实质变化生成新版本） |
| `POST` | `/api/branches/:id/qc/reports` | 按当前文字与时码生成质检报告 |
| `GET` | `/api/branches/:id/qc/reports/latest` | 最新报告（含失效标记与豁免状态） |
| `GET` | `/api/qc/reports/:rid` | 查看指定报告 |
| `POST` | `/api/branches/:id/qc/hits/:hid/exempt` | 对某条命中填写豁免理由（body: `reason`） |
| `DELETE` | `/api/branches/:id/qc/exemptions/:eid` | 撤销豁免 |
| `GET` | `/api/branches/:id/qc/export` | 质检专用下载（重新核验；未豁免命中/时间线错误/报告失效时 409，不生成 SRT） |

规则字段（PUT body）：`min_duration`、`max_duration`（秒）、`max_cps`（字符/秒）、`min_gap`（秒，可为 0）、`banned_words`（字符串按行或逗号分隔，或字符串数组）；阈值留空/省略表示不启用。

### 重剪重排接口与调用示例

预览请求字段：

| 字段 | 说明 |
| --- | --- |
| `source_start` / `source_end` | 连续原稿来源序号区间（≥1 整数，start ≤ end） |
| `new_start` / `new_end` | 区间在新版视频中的起止时码：`HH:MM:SS,mmm` 字符串，或非负整数毫秒；终点必须严格晚于起点 |

预览响应（200）含：`old_range`/`new_range`（区间原/新时码）、`shift_ms`（区间后平移量 = 新终点−原终点）、`scale_ratio`（等比系数）、`counts`（before/inside/after/changed 数量）、`affected[]`（每条受影响片段的 `ord`、`source_seqs`、`role=inside|after`、`old_timecode`、`new_timecode`、`time_changed`）、`errors`（换算问题）、`timeline_issues`（时间线问题）、`can_apply` 与一次性 `token`。结构不合法（跨界合并、来源缺失、区间无效）时直接返回 400 与 `recut_errors`，不发令牌。

确认时把同样参数与预览所得 `token` 原样回传；预览后分支发生编辑/拆分/合并/重置会得到 409 `{"preview_stale":true}`，需重新预览。

```bash
# 1) 预览：把分支 1 上来源片段 #2–#3 重排到新版视频的 00:00:05,000 ~ 00:00:10,000
curl -s -X POST http://localhost:3000/api/branches/1/recut/preview \
  -H 'Content-Type: application/json' \
  -d '{"source_start":2,"source_end":3,"new_start":"00:00:05,000","new_end":"00:00:10,000"}'
# => can_apply:true 时记录 token，并核对 affected[].old_timecode / new_timecode

# 2) 确认提交（毫秒整数亦可；token 必须来自针对当前分支状态的同参数预览）
curl -s -X POST http://localhost:3000/api/branches/1/recut/apply \
  -H 'Content-Type: application/json' \
  -d '{"source_start":2,"source_end":3,"new_start":5000,"new_end":10000,"token":"<预览返回的 token>"}'
# => {"ok":true,"counts":{"changed":3,...}}；若返回 409 preview_stale，请重新预览
```
